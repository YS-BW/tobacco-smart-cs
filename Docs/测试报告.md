## 二、RAG 检索效果测试

### 2.1 测试方法

选取 5 个烟草领域典型问题，观察完整 RAG 链路：向量检索 → 精排重排序 → LLM 生成回答。记录命中文档数、响应时间和回答质量。

### 2.2 测试结果

| 序号 | 测试问题 | 初检命中 | 精排保留 | 响应时间(ms) | 回答质量 |
|------|----------|----------|----------|-------------|----------|
| 1 | 黄鹤楼硬蓝的焦油量是多少？ | 6 | 3 | 11,098 | 准确，引用了具体产品参数 |
| 2 | 烟草专卖许可证怎么办理？ | 6 | 0 | 10,272 | 回答完整，但未命中精确文档 |
| 3 | 卷烟分为哪几类？ | 6 | 3 | 14,021 | 准确，列出烤烟型、混合型等分类 |
| 4 | 烤烟和晾烟有什么区别？ | 6 | 3 | 15,228 | 准确，对比了工艺和特点差异 |
| 5 | 中华香烟有哪些系列？ | 6 | 0 | 6,596 | 回答合理，但未命中精确文档 |

### 2.3 分析

```
精排命中率：3/5 = 60%（精排后保留 ≥1 篇文档的比例）
平均响应时间：11,443 ms
最快响应：6,596 ms（中华香烟系列）
最慢响应：15,228 ms（烤烟和晾烟区别）
```

**检索链路观察：**
- 向量检索阶段：所有问题均返回 Top-6 候选文档，初检覆盖率 100%
- 精排阶段：qwen3-rerank 对语义相关性进行重排序，部分问题（许可证办理、中华系列）精排后无文档超过阈值，系统正确降级为纯 LLM 回答
- 生成阶段：LLM 在有 RAG 结果时引用知识库内容，无 RAG 结果时基于自身知识回答

### 3.3 混淆矩阵

```
                  预测走RAG    预测跳过RAG
实际烟草问题        7 (TP)       3 (FN)
实际闲聊问题        1 (FP)       9 (TN)
```

### 3.4 评估指标

| 指标 | 公式 | 计算结果 |
|------|------|----------|
| 准确率 (Accuracy) | (TP+TN) / 总数 | 16/20 = **80.0%** |
| 精确率 (Precision) | TP / (TP+FP) | 7/8 = **87.5%** |
| 召回率 (Recall) | TP / (TP+FN) | 7/10 = **70.0%** |
| F1 分数 | 2×P×R / (P+R) | **77.8%** |

### 3.5 分析

- **精确率高（87.5%）**：系统判断"需要 RAG"时，87.5% 的情况确实需要，误触发率低
- **召回率偏低（70.0%）**：3 条烟草问题被误判为闲聊（电子烟、中华系列、烟叶种植），可能因为这些问题表述较口语化或边界模糊
- **总体准确率 80%**：对于 LLM 意图分类来说表现合理，可通过优化 prompt 提升

| 文件类型 | 文件大小 | 处理时间 | 分块数 | 速度 |

| Markdown | ~5 KB | 1,252 ms | 5 | ~4 KB/s |

说明：markitdown 本地解析速度极快，主要耗时在 DashScope Embedding API 调用。

### 5.4 性能瓶颈分析

```
对话响应时间构成：
├── RAG 检索 + 精排：~2-3 s（DashScope API 调用）
├── LLM 首 token 延迟：~3-5 s（Ollama 本地推理）
└── LLM 生成时间：~5-8 s（取决于回答长度）

优化方向：
- RAG 部分：Embedding 和 Rerank 可并行或缓存
- LLM 部分：本地 Ollama 受 GPU 性能限制
- 整体：平均 13s 对于知识问答场景可接受
```
